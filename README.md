## 项目介绍

**Zifeng AE2 Skills** 是「子枫技能树」与 Applied Energistics 2 的独立附属模组，提供 **装配超频、算力超频、合成之神的加护、算力之神的加护、万机之神的加护** 五项技能，并为技能点转换机增加 **使用 AE 能量生成技能点** 的供电方式。当前版本为 **1.2.0-beta**（预发布，见文末「已知问题」）。

后三项技能位于技能树的「神明之力」页签，tooltip 类型前缀显示为 `[诸神]`，标题为紫色，满级时各自解锁一个成就。

技能接入本体原有的学习、升级、开关和退款流程，让技能点投入直接作用于 AE2 自动合成系统。AE 供电功能则允许玩家使用已有 ME 网络为技能点转换机供能。

本仓库仅提供附属模组。运行时需要同时安装原作者技能树本体、AE2 及其依赖。

## 功能概览

| 功能 | 主要作用 | 最高等级 |
|---|---|---|
| 装配超频 | 提升分子装配室处理合成样板的速度 | 4 |
| 算力超频 | 增强合成 CPU 的并行处理能力 | 4 |
| 合成之神的加护 | 直接执行合成样板，高等级按批次完成合成（页签「神明之力」） | 5 |
| 算力之神的加护 | 一个实体 CPU 执行多个独立任务，共享扩展后的合成存储（页签「神明之力」） | 5 |
| 万机之神的加护 | AE 合成任务激活时，为产线上被样板驱动的机器追加原生工作次数；6 级验证 1 批后瞬成剩余批次（页签「神明之力」） | 6 |
| AE 能量生成技能点 | 技能点转换机从相邻 ME 网络取电，沿用本体规则生成技能点 | 机器开关，无需学习技能 |

### 装配超频

加速分子装配室处理合成样板。进度与能耗同步增加，单件合成的总耗能保持原有规则。

| 等级 | 速度倍率 | 本级升级费用 |
|---|---|---|
| 1 | ×2 | 500 点 |
| 2 | ×3 | 1,000 点 |
| 3 | ×4 | 2,000 点 |
| 4 | ×5 | 4,000 点 |

每台机器每 tick 最多完成一次合成，实际吞吐仍受供料、供电和输出空间影响。

### 算力超频

提升合成 CPU 的有效协处理器数量，使其能够向加工设备派发更多并行工作。

```text
有效协处理器数量 =（原生协处理器数量 + 1）× 倍率 − 1
```

| 等级 | 倍率 | 本级升级费用 |
|---|---|---|
| 1 | ×2 | 1,000 点 |
| 2 | ×3 | 2,000 点 |
| 3 | ×4 | 4,000 点 |
| 4 | ×5 | 8,000 点 |

普通超频加成上限为 4,096；不会将原生能力已超过该值的 CPU 降级。此技能面向 AE2 原生合成 CPU，实际加工速度仍取决于加工机器。

### 合成之神的加护

技能 id 为 `ae_assembler_infinite`，位于技能树的第 12 个页签「神明之力」，tooltip 类型前缀显示为 `[诸神]`，标题为紫色。合成样板可以由 CPU 直接执行，无需分子装配室；加工样板继续交给真实加工设备处理。

| 等级 | 每个 CPU 每 tick 的合成配额 | 本级升级费用 |
|---|---|---|
| 1 | 2 次 | 2,000 点 |
| 2 | 4 次 | 4,000 点 |
| 3 | 8 次 | 8,000 点 |
| 4 | 16 次 | 16,000 点 |
| 5 | 按批次完成，受服务器时间预算约束 | 32,000 点 |

合成按实际批次扣除材料和 CPU 派发能量，缺电时暂停，并正常处理容器返还。超大订单可跨 tick 续跑；满级不保证任意规模的订单都在单个 tick 内结束。

搬进「神明之力」页签只改变归属，升级费用仍沿用普通技能的等比费用表（2,000 点起逐级翻倍），不套用「万机之神的加护」的非等比费用。首次把该技能激活到 5 级时解锁同名原版成就（`divine_assembler_grace`），每个存档仅发放一次。

### 算力之神的加护

技能 id 为 `ae_cpu_infinite`，与「合成之神的加护」「万机之神的加护」同属第 12 个页签「神明之力」，tooltip 类型前缀显示为 `[诸神]`，标题为紫色。为同一个实体 CPU 提供多个拥有独立任务状态的 CPU，并共享实体 CPU 扩展后的存储容量。

| 等级 | CPU 总数，包含实体 CPU | 共享存储容量 | 本级升级费用 |
|---|---|---|---|
| 1 | 2 个 | ×2 | 2,000 点 |
| 2 | 4 个 | ×4 | 4,000 点 |
| 3 | 8 个 | ×8 | 8,000 点 |
| 4 | 16 个 | ×16 | 16,000 点 |
| 5 | 按需增加，不设技能数量上限 | 无限 | 32,000 点 |

各 CPU 的任务可独立选用、查看与取消。满级同时解除实体与虚拟 CPU 的协处理器限制；材料、电力、加工机器速度及服务器时间预算继续生效。

关闭或降低技能等级后，已有任务继续完成，超出新上限的空闲虚拟 CPU 会被回收。此技能面向 AE2 原生合成 CPU。

升级费用同样沿用普通技能的等比费用表，不套用「万机之神的加护」的非等比费用。首次把该技能激活到 5 级时解锁同名原版成就（`divine_cpu_grace`），每个存档仅发放一次。

### 万机之神的加护

技能 id 为 `ae_divine_machine_grace`，位于技能树的第 12 个页签「神明之力」。AE 合成任务激活时，为这条产线上被样板驱动的机器追加原生工作次数：同一 tick 内重复调用机器自己的 `tickingRequest` / `BlockEntityTicker.tick`，不改动 tick 频率与进度字段。

| 等级 | 倍率 | 本级升级费用 |
|---|---|---|
| 1 | ×2 | 1,000 点 |
| 2 | ×8 | 5,000 点 |
| 3 | ×16 | 10,000 点 |
| 4 | ×128 | 50,000 点 |
| 5 | ×1024 | 100,000 点 |
| 6 | 瞬成 | 1,000,000 点 |

费用为非等比递增，不套用 `base << n` 的等差数列。

**6 级：瞬成。** 一个样板要跑很多批时，先按 5 级速率让机器真做 **1 批**作为验证；只要这一批的预期产物真的回到了合成任务，该样板**剩余的全部批次**立刻记账完成——材料直接从合成 CPU 的内部库存扣除，产物按 AE2 原生路径投递（合成任务 → ME 存储 → CPU 库存三级兜底），不再需要机器，也不再消耗 AE 电量。

- **验证判据是产物回流，不是「推送成功」。** 观察点是 `CraftingCpuLogic.insert`：只有合成任务真的接纳了该样板的产物才算通过。样板推送成功本身不能作为证据——空壳机器、吞材料的机器同样会让 `pushPattern` 返回 `true`，用它做判据等于凭空刷物品。
- **验证期间该样板被锁住。** AE2 的 `executeCrafting` 在一个 tick 内会反复推同一样板（只要供应器不 busy），一个 tick 就能推出很多批。不锁就会出现「验证期间多批在飞」，随后按剩余批数结清会重复记账、直接超产。锁定只针对"正在取证的该样板 + 该 CPU"，验证一结束立刻放开，不影响同一任务的其它样板。
- **超时约 10 秒（200 tick）。** 没等到产物回流就放弃该样板、永久不再尝试，回落 5 级加速——避免空壳机器把任务反复卡住。
- **免电。** 瞬成的那些批次不做机器加工，因此不计也不扣 `calculatePatternPower`；验证的那 1 批照常扣电。机器的耗电不补偿、也不追缴。
- **只接管处理样板。** 合成台样板仍归「合成之神的加护」瞬成，两者不重叠。
- **只对 AE2 原生合成 CPU 生效**（含其子类与虚拟 CPU）。第三方自有 `ICraftingCPU` 实现不产生 `ExecutingCraftingJob`，拿不到任务与批次计数，因此只享受 5 级加速。
- **不设批次硬上限。** 结算受每 tick 2.5 ms 时间预算约束，一次没结完就留到下一 tick 继续。

**生效条件：** 仅当该网格上存在未暂停的活跃合成任务（`CraftingCpuLogic.hasJob()` 且 `!isJobSuspended()`），并且样板确实推给了机器（观察 `PatternProviderLogic.pushPattern` 成功）时才生效；任务完成、取消或暂停后，下一 tick 立即停止加速。

**兼容性：** 只使用 AE2 公开接口（`PatternProviderLogicHost.getTargets()`、`ICraftingMachine`、`IGridTickable`、`BlockState.getTicker`），任何能被 AE 样板正常驱动的机器都会自动生效，无需逐个适配；机器自身的耗电、产出与容器返还规则全部保留。加速目标只来自「样板真的推给了它」这条路径，不会把整张网络上的机器一并加速。

**性能保护：** 每个服务器 tick 共用一份时间预算（单片 2.5 ms）。单台机器每 tick 的额外次数不超过 1,023，全体合计不超过 8,192；预算耗尽的部分自动顺延到后续 tick。

**与装配超频的叠加：** 两个技能不叠加。万机之神在本 tick 实际加速过某台机器时，装配超频对该机器整段让路（不是降级相加），因此单台机器每 tick 只有一份额外 tick。

首次把该技能激活到 5 级时解锁同名原版成就（`divine_machine_grace`），每个存档仅发放一次；首次点到 6 级时再解锁隐藏标题式的成就「超越万机？？？」（`divine_transcendence`，附一道原版雷声，只放给达成者本人），同样每个存档仅一次。5 级成就的门槛被钉死在 5，等级上限提升到 6 不会让老存档失去它。

### 技能生效规则

- 五项技能均为全局技能，按在线且开启对应技能的玩家中，所选生效等级的最高值计算。
- 学习、开启和调整等级沿用本体的全局技能权限要求，需要 OP 权限。
- 多名玩家提供相同技能时，等级取最高值，倍率不叠加。
- 玩家关闭技能或登出后，服务器重新计算生效等级。

## AE 能量生成技能点

本附属为本体的 **技能点转换机** 增加「使用 AE 能量」开关。开启后，转换机从相邻 ME 网络抽取 AE 能量，并将其折算为本体接受的 FE 当量，沿用本体的转换阈值生成技能点。

### 使用步骤

1. 放置本体技能点转换机，确认机器已绑定主人。
2. 让转换机任意一个面紧贴可接入 ME 网络的 AE 线缆或设备，并为网络提供电力。
3. 使用机器主人账号打开转换机界面，开启「使用 AE 能量」。
4. 按本体规则累积转换进度，达到阈值后生成技能点。需要更高吞吐时，可按需使用本体的「无限制输入」开关。

| 项目 | 行为 |
|---|---|
| 默认状态 | 关闭，继续使用原有 FE 供电 |
| 接入范围 | 仅检查相邻六个面，不提供无线或远距离取电 |
| 换算规则 | 跟随 AE2 的 AE / FE 汇率；默认 `1 AE = 2 FE` |
| 每点消耗 | 使用本体配置的技能点转换阈值，不另设固定 AE 价格 |
| 输入速率 | 沿用本体输入速率和缓冲限制；默认每 tick 最多补足当前一个技能点所需进度 |
| FE 与 AE | 两种供电方式互斥，开启 AE 供电时关闭 FE 输入 |
| 网络暂时缺电 | 仍有可用连接时保留进度，等待供电恢复 |
| 网络断开 | 交由本体原有的断供处理逻辑执行 |
| 操作权限 | 只有机器主人可以切换 AE 供电，无主机器拒绝切换 |
| 可选提示 | 安装 Jade 后可显示 ME 网络连接状态提示 |

AE 供电功能与五项技能分别检查兼容性。本体转换机接口不匹配时，该功能会禁用并记录原因，其余技能仍按各自的兼容检查结果加载。

## 运行环境与兼容范围

| 项目 | 要求或验证基准 |
|---|---|
| Minecraft | 1.21.1 |
| Java | 21 |
| 加载器 | NeoForge 21.1.234 起，限 21.1 系列 |
| 必需模组 | 原作者子枫技能树、AE2，以及 AE2 自身依赖 |
| 编译及基础验证版本 | 技能树 1.5.0、AE2 19.2.17、NeoForge 21.1.234 |
| 安装侧 | 客户端与服务器均需安装 |
| 可选模组 | Jade；仓库内另有部分 AE2 生态模组的适配代码 |

算力超频和算力之神的加护不对第三方完全自有的合成 CPU 实现提供通用加成。第三方复用原生 CPU 的情况，以及 AdvancedAE、ExtendedAE、ExtendedAE Plus、UFO 等专用适配，依赖对应版本的实现与接口，不能据此推断所有设备和版本均已兼容。

万机之神的加护只依赖 AE2 公开的样板供应器与机器接口，不做逐模组适配：凡是能被 AE 样板正常驱动的机器（含第三方机器）都会自动生效，逐个适配并非必需。其加速量同时受每 tick 时间预算与硬上限约束，预算耗尽的部分顺延到后续 tick，慢机器上实际倍率可能低于所选等级。

启动时会检查关键接口和注入位置，发现不匹配会给出加载诊断。依赖声明允许安装其他版本，不代表这些版本全部经过验证。技能树 1.5.6 / NeoForge 21.1.248 的完整组合及用户存档尚未在本项目基准环境中实测。

## 安装与升级

1. 从 [Releases](https://github.com/yhoops/zifeng_ae2speed_skills/releases/latest) 下载 `zifeng_ae2_skills-<版本>.jar`。GitHub 自动提供的 Source code 压缩包用于源码构建。
2. 安装 [原作者技能树本体](https://www.curseforge.com/minecraft/mc-mods/zcs) 与 [AE2](https://modrinth.com/mod/ae2)，并补齐各自依赖。
3. 将附属 JAR 放入游戏实例的 `mods` 目录；多人环境在客户端和服务器安装相同版本。
4. 启动后，在技能树查看五项技能（合成之神、算力之神、万机之神三项位于第 12 个页签「神明之力」），在技能点转换机界面查看 AE 供电开关。

升级前退出游戏或停止服务器，并备份世界。用新 JAR 替换旧附属，避免同时保留多个版本。1.1.6 升级到 1.1.7 无需降低技能等级、取消合成任务或编辑存档：技能 id、等级表、费用与已有数据全部沿用，两个旧技能只是改归「神明之力」页签。

**请使用原作者本体。** 已内置这五项技能的定制本体会造成重复注册，本附属检测到后将停止加载。带有虚拟 CPU 任务的世界应保持附属安装；在缺少附属的状态下打开并保存世界，可能丢失附属管理的任务数据。

## 1.2.0-beta 更新

### 新增：万机之神的加护 6 级「瞬成」

- 等级上限由 5 提升到 6，第 6 级费用 1,000,000 点（非等比序列 1,000 / 5,000 / 10,000 / 50,000 / 100,000 / 1,000,000）。技能树里 10 万以上的费用现在带千分位显示（`1,000,000`），10 万以下的既有费用一字未变。
- 6 级的效果不是更高的倍率（倍率仍是 ×1024），而是性质变化：先做 1 批验证，验证通过就把该样板剩余的全部批次瞬间记账完成。
- 验证判据取严格版——必须观察到合成任务真的从 `waitingFor` 里扣掉了该样板的产物（用 `insert` 前后的 `waitingFor` 差值判定），而不是 `pushPattern` 返回 `true`。注意不能用 `insert` 的返回值：那是下游领取方拿走的量，产物直接进 ME 存储的订单恒为 0。
- 验证期间锁住该样板，保证同一时刻只有 1 批在飞；超时 200 tick 则放弃并永久回落 5 级。
- 瞬成批次免电；验证批照常扣电。机器耗电不补偿也不追缴。
- 仅接管处理样板，且仅对 AE2 原生合成 CPU（含虚拟 CPU）生效；合成台样板仍归「合成之神的加护」，第三方 CPU 仍只享受 5 级加速。
- 「算力之神」「合成之神」的等级上限、费用与效果完全不变。

### 新增：成就「超越万机？？？」

- 首次把「万机之神的加护」点到 6 级时发放（`divine_transcendence`），图标为 `minecraft:lightning_rod`，`hidden: false`，未达成时也挂在进度界面当一个看不懂的条目。
- 达成者本人客户端会响一道原版雷声（`entity.lightning_bolt.impact` + `entity.lightning_bolt.thunder` 双段，音高与音量照抄原版落雷并拉长），其他人只在聊天栏看到公告。
- 成就按<b>该玩家自己的</b>技能等级判定，而技能效果是全服取最高：没点到 6 级的 OP 拿不到这条成就，这是有意为之。
- 5 级成就 `divine_machine_grace` 的门槛被钉成常量 5，老存档不会因为上限提高而失去它。

- `logo.png` 由 512×512 真彩（465 KB，占旧 jar 76%）换成 256×256 / 64 色调色板 PNG，仅换图就使 jar 从 609,705 B 降到 175,387 B；接完 1.2.0-beta 全部功能后最终约 186 KB。原图备份在 `backups/`。

### 实现

- 新增 `divine/DivineTranscend`（取证与结算状态机）、`mixin/ae2/DivineCpuMixin`（观察 `executeCrafting` / `insert` / `tickCraftingLogic`）、`crafting/CraftingDelivery`（从 `InstantCrafting` 抽出的三级兜底投递，两处共用）。
- `PatternProviderPushMixin` 增加 `pushPattern` HEAD 的取消点，用于验证期间上锁。
- 三个不可逆决定的来由记在 `docs/adr/0001-divine-grace-level-6.md`。
- 「算力之神」5 级分裂算力会绕过 AE2 原生的 `executeCrafting`（改由 `UnlimitedDispatch` 直连 `pushPattern`），因此 6 级的取证标记在那条路径上也补了一份——否则同时点满分裂算力的玩家会看到 6 级完全不生效。

### 修复：兼容预检不再误杀可选注入

1.1.7 起，`compat/Compatibility` 的结构预检把带 `require = 0` 的**可选**注入也当成必检契约，于是宿主 1.5.0 上（没有 1.5.5 才引入的 `SkillTreeScreen#refreshDisplayedCategories`）客户端会直接拒绝加载附属，报「缺少混入目标 / Missing hook」。现在预检会读出同一注解的 `require`，为 0 时跳过「缺少混入目标」「缺少注入位置」两条判定，与 Mixin 自身语义对齐；`require >= 1` 的契约照旧强制校验，真正的结构漂移依然会在启动时炸出来。

这条修复的验收就是「宿主 1.5.0 的 dev client 能起来并跑完 6 项客户端断言」——服务端 GameTest 根本不检查 client mixin，1.1.7 的 GameTest 全绿掩盖了它。

### 修复：瞬成在实测中不生效

用户实测发现「验证批正常发出、剩余批次却从未结清」。根因是验证判据读错了返回值：`CraftingCpuLogic.insert` 返回的是**下游领取方**（`job.link`）拿走多少，产物直接进 ME 存储、无人领取的订单恒返回 0，而 `waitingFor` 其实已经被扣掉了——于是这类订单永远验不过，200 tick 超时后回落 5 级。

现改为比较 `insert` 前后 `waitingFor` 的差值（`delta > 0` 才算被任务接纳），与谁领走无关，且依旧严格（空壳机不会让 `waitingFor` 下降）。同时新增端到端 GameTest `divineTranscendSettlesVerifiedPattern`：真机路径放一个箱子当机器、下单 100 份，断言「只推 1 批 → 回流 1 个产物后验过 → 再 tick 一次整单结清、箱子仍只有 1 批」。

## 1.1.7 更新

### 新增：万机之神的加护

- 技能 id `ae_divine_machine_grace`，位于新增的第 12 个页签「神明之力」。AE 合成任务激活时，为这条产线上被样板驱动的机器追加原生工作次数。
- 实现方式是同一 tick 内重复调用机器自己的 `tickingRequest` / `BlockEntityTicker.tick`，不改动 tick 频率、进度字段或任何机器内部状态字段，因此机器自身的耗电、产出与容器返还规则全部保留。
- 倍率 ×2 / ×8 / ×16 / ×128 / ×1024，费用 1,000 / 5,000 / 10,000 / 50,000 / 100,000 点，为非等比递增。
- 目标发现只走「样板真的推给了它」这条路径：由 `PatternProviderPushMixin` 记录成功推送的样板供应器，再取其配置朝向相邻的装配机或带方块 ticker 的机器；不使用 `IGrid#getActiveMachines` 做全网格枚举，避免把技能从「这条产线」放大成「整个基地」。
- 三重闸门：有技能等级；该网格存在未暂停的活跃任务（含第三方 `ICraftingCPU#isBusy()` 兜底）；供应器属于该活跃网格。任务完成、取消或暂停后下一 tick 立即停止。
- 兼容性只依赖 AE2 公开接口（`PatternProviderLogicHost#getTargets()`、`ICraftingMachine`、`IGridTickable`、`BlockState#getTicker`），第三方机器无需逐个适配。

### 新增：神明之力页签

- 宿主把页签数写死为字面量 11，本次用 6 处 `@ModifyConstant` 精确扩到 12，并用 `Arrays.copyOf` 扩展页签标题键与强调色数组，不改写宿主长方法。
- `require` 数量与实际命中数一致，宿主升级导致失配时由 `MixinFailureHandler` 直接报错停止，不会静默错位。
- 全局页签过滤掉神明技能，避免同一技能同时出现在两个页签；页签强调色 `0xFFB388FF`，类型前缀 `[诸神]`。

### 变更：合成之神 / 算力之神迁入神明页签

- 「合成之神的加护」（`ae_assembler_infinite`）与「算力之神的加护」（`ae_cpu_infinite`）改归「神明之力」页签，tooltip 前缀改为 `[诸神]`、标题改为紫色。
- 仅归属变化：技能 id、等级表、费用（仍走普通等比费用表，不套用万机之神的非等比费用）与效果完全不变，已有存档无需迁移。

### 新增：三个满级成就

- `divine_machine_grace` / `divine_assembler_grace` / `divine_cpu_grace`，分别在有人首次把对应技能激活到 5 级时发放。
- 走原版 advancement 系统，发放状态由 `SavedData`（`zifeng_ae2_skills_divine_grace`）落盘，每个存档只发放一次，重启服务器不会重复触发；换存档后允许重新发放。
- 会话内加内存短路，避免满级时每 tick 查询存档；成就未在数据包中加载时输出 warn 日志，不再静默跳过。

### 优化：时间预算与公平性

- 万机之神的加速与「无尽装配」「分裂算力」共用同一份每 tick 时间预算：单片 2.5 ms，共享池硬顶 20 ms / tick 且不超过 tick 起点后 45 ms，预算耗尽的部分自动顺延到后续 tick，不会丢弃。
- 单台机器每 tick 的额外次数不超过 1,023，全体合计不超过 8,192，避免一台机器或一张网络独占整帧。
- 目标轮转指针只在「该台机器完整服务完」时推进，提前撞到时间或次数上限时原地保留，修复了队首机器吃满配额、队尾机器被系统性饿死的问题。
- 同一 tick 出现第二个入口时先做去重再清状态，避免让路判定失效导致同一台机器吃到两份额外 tick。

### 优化：与装配超频的互斥

- 万机之神在本 tick 实际加速过某台机器时，装配超频对该机器整段让路，而不是降级相加，单台机器每 tick 只有一份额外 tick。
- 让路判定读取「本 tick 真的执行过额外 tick」的集合，不是上一 tick 的目标快照，因此不存在一 tick 的相位差。

- 客户端冒烟与服务端 GameTest 补充神明页签、成就与加速相关的检查用例。

## 常见问题与反馈

| 问题 | 排查方向 |
|---|---|
| 五项技能没有出现 | 检查两端是否安装附属、依赖是否完整，以及启动日志中的兼容诊断 |
| 加工机器没有瞬间完成 | 合成之神的加护仅直接执行合成样板，加工样板仍等待真实机器输出 |
| 第三方 CPU 没有技能加成 | 对照上方兼容范围，第三方自有 CPU 不保证获得加成 |
| 转换机没有 AE 开关 | 检查附属安装情况和转换机兼容诊断，确认本体版本接口可用 |
| 开启 AE 后不产生技能点 | 检查机器主人、相邻网络、供电、红石状态、输入速率与本体转换阈值 |
| 容量提示出现备用格式 | 显示操作已恢复，任务逻辑不受此恢复操作影响；反馈时附上 `logs/latest.log` |

## 从源码构建

安装 JDK 21 后，在仓库根目录执行以下命令。首次构建需要联网下载依赖；构建脚本自动获取并校验技能树 1.5.0 编译基准，本体、AE2 和第三方依赖不会打包进附属。

Windows：

```powershell
.\gradlew.bat build
```

Linux / macOS：

```sh
./gradlew build
```

产物位于 `build/libs/`。`gradle.properties` 定义附属、AE2 和 NeoForge 版本。

### 验证命令

| 命令，Windows 示例 | 检查内容 |
|---|---|
| `.\gradlew.bat runClient` | 启动开发客户端 |
| `.\gradlew.bat runClient -PclientSmoke` | 实际 CPU 控件绘制、悬停、容量边界、异常恢复与相关界面检查 |
| `.\gradlew.bat runGameTestServer -Pae2Tests` | 合成、虚拟 CPU、持久化与 AE 供电等服务端检查 |
| `python tools/verify_release.py` | 检查翻译键、发布包内容及兼容类索引 |
| `python tools/verify_compat.py` | 检查技能数值、溢出饱和、降级、时间预算及适配注册 |

Python 校验脚本在构建后运行；`verify_compat.py` 需要设置 `JAVA_HOME` 或将 JDK 21 加入 `PATH`。Linux / macOS 将 Gradle 命令替换为 `./gradlew`。

可使用 `-PcompatMods=<目录>` 加载本地第三方 JAR，使用 `-PhostJar=<路径>` 或 `-Pae2Jar=<路径>` 指定运行时依赖；这些参数不会改变源码中的编译基准。

## 已知问题（1.2.0-beta）

这是一个**预发布版本**，主要目的是一次性接上「万机之神的加护」6 级的瞬成效果。核心逻辑只用 GameTest 与客户端冒烟验证过，**尚未在真实存档的大规模产线上跑够样本**，请勿直接用于不可回滚的重要存档。

- **瞬成仅做了单机 GameTest 级别的验证**：1 圆石 → 1 钻石、100 批量、单一样板、真实供应器路径。「多步合成（有中间产物）」「带容器的配方」「同一样板被多个 CPU 并发使用」这几类分支只有代码层推理，缺少实测样本。
- **验证判据刚刚改过一次**：早期版本读了 `CraftingCpuLogic.insert` 的返回值，而那是下游领取方拿走的量，产物直接进 ME 存储的订单恒为 0，导致瞬成完全不触发。现已改为比较 `waitingFor` 差值，但这条路径的实测样本仍然很少。
- **200 tick 超时后不再重试**：验证失败（机器是空壳、机器吞料、产物进不了合成账本）时该样板会**在本任务内**永久退回 5 级加速，不会再次尝试瞬成。换任务或重新下单才会重新取证。
- **两条样板产出同一物品时不瞬成**：为避免把 B 线机器做出的产物记到 A 线头上，出现歧义时两条都退回 5 级。这是刻意的保守选择，不是 Bug，但会让人觉得「有时不生效」。
- **第三方合成 CPU 不生效**：只对 AE2 原生合成 CPU（含虚拟 CPU 与本模组的适配形态）生效；AdvancedAE、UFO 等第三方 CPU 形态仍只享受 5 级 ×1024。
- **合成台样板不走瞬成**：6 级只处理加工样板；合成台样板仍归「无尽装配」的瞬成逻辑。
- **5 级分裂算力的交互刚修过**：`UnlimitedDispatch` 会绕过原生 `executeCrafting`，早期版本会让 6 级对点满分裂算力的玩家完全失效，现已补上取证入口，但两个技能同时满级时的组合行为样本很少。
- **成就与雷声**：`divine_transcendence`（超越万机？？？）按玩家自己的等级发放，而技能效果是全服取最高等级——没点到 6 级的人拿不到这条成就，属预期行为。

遇到异常请附上 `logs/latest.log`、机器类型、样板内容与订单规模，这些信息足以定位到上面列出的哪一类分支。

**验证状态：** 1.2.0-beta 通过 Gradle 构建、服务端 GameTest（**5/5**，含新增的瞬成端到端用例）、客户端冒烟（6 项断言，含费用千分位、5 级 ×1024 与 6 级「瞬成」文案）、`verify_release.py` 与 `verify_compat.py`；交付前另做了一轮只读评审并修掉 1 个严重 + 5 个中等 + 2 个轻微问题，用户实测反馈后又修掉「验证判据读错 `insert` 返回值」这一根因（见下），上述验证在修正后全部重跑通过。真实产线上的瞬成行为仍需手动实测。1.1.7 通过 Gradle 构建、`verify_release.py` 与 `verify_compat.py` 校验；1.1.6 的基础客户端和 UFO FUTURE 3.0.0-beta.2 同装客户端检查通过；完整服务端 GameTest 中，“大型多步骤订单按原生 tick 完成”的断言存在已记录的失败，当前不保证整套服务端测试全部通过。构建成功也不等同于所有游戏内行为均已通过验证。
